# 予你花园 · For Linxuan

为陈琳萱设计的私人鲜花网页。奶油白、鼠尾草绿和淡粉色，配以中文衬线字、花笺、拍立得和信封。

## 已实现

- 全站花卉使用精细 SVG：芍药、郁金香、雏菊均由独立花瓣曲线、渐变明暗、高光、花脉、叶脉和花蕊组成，可无损放大。
- 首页与详情轻触绽放、花朵轻摆、拖动轻转，详情支持双指缩放。手机首页保留纵向滑动。
- 自然花瓣散落与花瓣雨：先舒展、轻轻向外扬起，再随重力、风与摆动落下；花瓣使用 SVG 轮廓。
- 所有绽放入口共享播放锁。动画播放中按钮禁用，花朵点击忽略；整段花开和最后一片花瓣播放完才解锁。没有定时强制重启，也不会截断旧花瓣。键盘长按不会重复触发。
- 本机相机、系统相机降级、相册选图和示例体验；照片压缩后保存在当前浏览器 IndexedDB。
- 上传或拍摄照片先识别花卉主体，通过后选择本机取色绘制或 AI 视觉绘制，SVG 通过真实渲染校验后入藏。收藏、筛选、原图回看、删除与撤销仍然可用。
- 导出完整 `.svg` 矢量资产、查看 SVG 路径/渐变数量与源码，以及导出 PNG 花笺。
- 可拆开的专属信笺、用户点击后才播放的轻柔合成音乐、移动端导航和减少动态效果偏好。

## 先识别主体，再绘制

上传和相机照片均需先通过 `assessFlowerSubject` 的独立视觉请求。该请求只返回识别 JSON，不输出 SVG。允许条件为：`mainSubject="flower"`、`flowerPresent=true`、`flowerIsPrimary=true`，且模型自评 `confidence >= 0.85`。人物/物品/风景主体、背景中的小花、模糊或无法确定的图片均停止，不调用绘制、不入藏。置信分数是模型的主观判断，不等同于经过校准的识别准确率。

识别结果在内存中绑定当前照片、通过视觉验证的配置对象和五分钟有效期，克隆或换图不能复用。绘制入口也会检查通过凭证，避免漏调前置识别。主体不合格时禁用生成按钮，重新选择照片或更换模型后才可重新判断；识别超时/网络异常只允许重试识别。

普通上传照片使用本机取色模式时也要先发送至用户配置的视觉模型识别主体。未配置模型不能生成，界面会明确说明照片发送用途。只有随站点打包的已知鲜花示例可离线体验本机绘制；不能把该例外用于用户上传照片。AI 绘制通常包含一次主体识别和一次绘制调用；识别失败不产生绘制调用。

## AI 直接输出精细 SVG

`dist/ai.js` 的 `FLOWER_SYSTEM_PROMPT` 通过真正的 `role: "system"` 消息发送。模型根据花照直接编写 JSON 中的完整 `svg` 字符串，同时返回花名、花语、主色和造型说明。要求包括：

- 根据照片绘制独立 Bézier 花瓣、自然边缘、叠层与卷曲、透明高光和遮挡暗部，细描叶脉、花丝与花蕊。
- 通常绘制 40–140 个可见细节、20–80 条路径和 4–12 组渐变；最低需有 16 个图形、8 条路径、2 组渐变。简单花型通过脉络与花蕊增加细节，不凭空加花瓣。
- 使用透明的 `480 × 600` 画布，完整保留花朵、留出边缘，直接返回可用 SVG 源码。
- 使用静态矢量标签与展示属性；禁止脚本、事件、CSS、嵌入图片、外部资源、动画标签和滤镜。
- SVG 字符串使用单引号 XML 属性与单行源码，减少长代码放入 JSON 时漏转义的情况；返回内容仍必须通过严格 JSON 解析。

AI 路径没有花型枚举或模板回退。只在模型 SVG 的真实元素之间清理无内容的 `<>` / `</>` 空片段，然后执行全部严格校验；不会修补实际标签、路径或属性。源码不完整、不安全或细节不足会明确失败，保留原照让用户重试。图形细节数量是最低格式门槛，最终审美质量仍取决于所选视觉模型与照片。

请求优先使用严格 `response_format: json_schema`，固定字段、数据类型、字符串枚举和 `additionalProperties: false`；长度、数值范围与 `schemaVersion === 1` 由客户端强制检查，兼容严格模式的公共子集。仅当服务明确拒绝结构化参数时，才移除该参数重试一次；客户端检查仍然有效。成功响应若无效或被截断，明确失败并保留照片，不自动追加付费重绘。接口约定参照 [OpenAI Structured Outputs 官方文档](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat)。

MiniMax 兼容说明：`schemaVersion` 在请求中只声明 `integer`，不携带数值枚举 `[1]`。后者会触发该网关的 HTTP 400 / 2013 类型解析错误，导致图形视觉验证能通过，但花卉识别尚未调用模型便失败。版本值仍在客户端严格检查。请求层同时识别标准 `error`、顶层参数错误及 HTTP 200 内的 `base_resp` 失败；只对明确拒绝的结构化参数执行兼容请求。错误提示标明「图片输入验证」「花卉主体识别」或「SVG 绘制」阶段，以及 HTTP 状态和数值服务代码，不展示可能包含密钥的原始服务报错。服务代码参照 [MiniMax 官方错误码](https://platform.minimax.io/docs/api-reference/errorcode)。

对 MiniMax 官方域名上的 `MiniMax-M3.1-Flash`，使用其支持的 `reasoning_effort: "medium"`，控制默认最高思考强度带来的延迟；不关闭该模型必需的思考能力，也不向其他模型或兼容网关附加此参数。参照 [MiniMax OpenAI 兼容接口文档](https://platform.minimax.io/docs/api-reference/text-openai-api)。

2026-10-28 实测：`https://api.minimax.cn/v1` + `minimax-m3.1-flash`，使用内置芍药照片，图片验证、主体识别与 SVG 绘制均返回 HTTP 200。模型输出经上述空片段规范化和完整校验后得到 122 条路径、10 组渐变、134 个图形，浏览器实际解码与可见像素检查通过；这次绘制耗时约 94 秒。实测未使用用户上传的原照，也未保存密钥。

`dist/svg.js` / `dist/svg-grammar.js` 在展示、缩略图、保存前及导出时校验 XML 结构、标签与属性白名单、唯一 ID、引用类型、路径命令参数数量、圆弧标记、变换参数、有限数值和节点/体积预算。生成图固定 `viewBox="0 0 480 600"`，归一化独立文件的宽高；藏在 defs/蒙版中的路径不计入可见细节门槛。SVG 展示会为 ID 添加实例前缀，避免首页和详情的渐变相互污染。模型内容无法执行代码或加载外链。

入藏前还需经过 `dist/svg-render.js`：浏览器 DOMParser 解析、有效颜色检查、实际 SVG 解码，以及 `240 × 300` 画布的 alpha 像素检查。完全透明、画布外、空白、过小或解码失败的作品不能保存。只有通过全部检查才生成缩略图和写入 IndexedDB。结构与渲染可用性可以检查，识别准确率和审美质量仍取决于模型及照片。

## 配置视觉模型

1. 点击「AI 创作」或拍花表单中的「配置视觉模型」。
2. 填写 OpenAI 兼容 Base URL、API Key、视觉模型 ID。Base URL 支持 `/v1` 或自定义路径，完整 `/chat/completions` 会自动归一化。
3. 可读取候选模型；已明确为纯文本的模型会被过滤。
4. 点击「验证视觉能力」。页面发送本机随机图形，正确识别颜色和形状后才能保存；会产生一次模型调用。
5. 保存后拍花流程启用 AI 精细绘制，也可关闭开关使用本机取色 SVG；上传照片仍需先通过主体识别。
6. 生成后自动入藏。在详情选择「导出 SVG」，或展开「查看这朵花的 SVG 细节」检查源码。

API Key 仅在当前页面内存中使用，不写入 localStorage、IndexedDB、源码、日志或导出文件。设置对话框关闭时清空密码输入框，刷新后需重新填写和验证。只保存非敏感 Base URL 与模型 ID。模型变更需重新验证。

浏览器直连 `POST /chat/completions`，照片以 `image_url` Base64 Data URL 发送，密钥放在 Authorization 请求头。服务商需允许本站的 CORS 请求；非本机地址需 HTTPS。支持 `/models`、两种 token 上限参数兼容、取消、超时及错误提示。没有内置密钥或后端代理。真实服务质量需由用户在页面内配置后验证。

## 旧藏品与存储

原本的三种赠花与本机花型会更新为精细 SVG，旧缩略图也会刷新。旧 AI 独立曲面、空间路径和自定义形状由 `dist/legacy-svg.js` 在本机按原始控制点转绘成 SVG，不运行 Three.js、不套用新花型，保留原始记录、原照、名字和收藏状态。详情明确标记「藏品矢量转绘」，可用原照新建 AI 精细 SVG 版本。旧数据无法转换时，保留原记录并提示重新绘制。

藏品、照片和收藏均保存在当前浏览器的 IndexedDB，不跨设备同步。清除网站数据或某些隐私浏览模式会影响保存。可导出 SVG 或 PNG 花笺留存。摄像头需要浏览器授权与 HTTPS/localhost。上传或相机照片会先发送至用户填写的模型服务识别主体；本机取色绘制随后在浏览器完成，AI 绘制还会将同一照片发送以生成 SVG。内置示例的本机绘制不发送照片。

Three.js、WebGL 渲染器、GLB 导出器与几何编译器已移除。网站运行不依赖 CDN，静态资源约 826 KB（包括字体、照片与 SVG）。采集区的摄影素材与原始花照仍作为照片保留。

不需要安装依赖或构建：

```bash
cd /home/haydenai/Sources/FlowersforChenLinXuan/linxuan-garden
npm run dev
```

访问 `http://127.0.0.1:4173`。运行检查：

```bash
npm run check
```

检查包括 HTML/ARIA、交互引用、静态资源、模块语法、三种精细 SVG、矢量导出、旧藏品转换、快速点击互斥、花瓣起落轨迹、最后一片花瓣完成后的清理、减少动态效果、system 消息及图片请求、SVG 安全与细节门槛、独立主体门槛（人物、物品、背景花卉、不确定/低自评）、凭证与照片绑定、严格 JSON 结构、MiniMax 数值枚举与 2013 错误回归、兼容请求次数和失败阶段提示、路径语法、视觉验证、模型列表、鉴权/限流/超时/取消和密钥隔离。使用模拟服务，不使用真实密钥、不产生付费调用。`scripts/browser-check.html` 提供独立浏览器检查页，验证实际解码、可见像素、透明/画布外/过小/无效颜色拦截，以及模拟服务中的先识别后绘制顺序。可在项目根目录启动 HTTP 服务后访问 `/scripts/browser-check.html`。真实模型的图片判断质量与摄像头权限仍需在用户设备与所选服务上验证。

## 文件

- `dist/index.html` / `dist/style.css`：页面结构、视觉与移动端布局。
- `dist/assets/flowers/*.svg` / `dist/flower-assets.js`：精细植物矢量原稿与内联资源。
- `dist/flower.js` / `dist/svg.css`：SVG 展示、轻转、缩放、绽放、本机取色与导出。
- `dist/effects.js`：共享播放锁、自然花瓣轨迹及动画完成清理。
- `dist/svg.js` / `dist/svg-grammar.js`：SVG 结构、属性、路径语法、统计与实例 ID 隔离。
- `dist/svg-render.js`：浏览器解码、颜色与可见像素验证。
- `dist/legacy-svg.js`：旧藏品的本机矢量转绘。
- `dist/ai.js`：视觉验证、独立花卉主体识别、绑定凭证、严格输出协议与精细 SVG 绘制。
- `dist/ai-settings.js` / `dist/ai-settings.css`：模型设置。
- `dist/app.js`：藏品、拍照、AI 绘制、音乐、导出与信笺交互。
- `dist/assets/peony.webp`：原有 imagegen 芍药照片，用于采集区与示例。
- `dist/assets/*.woff2`：随站点打包的字体，许可文本同目录保存。
- `.openai/hosting.json`：原有 Sites 身份和静态发布目录，保持原访问范围。
